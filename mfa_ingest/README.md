# Quickstart — End-to-End Steps (PowerShell)

All commands below are intended for **Windows PowerShell**.
Before you start:
- Ensure **Python** is installed and the version is **>=3.10,<3.14**.
- Ensure **Poetry** is installed.

## 1) Clone the repository and enter it

    git clone <REPO-URL>
    cd <REPO-FOLDER>

## 2) Create a project-local virtualenv and install dependencies

Configure Poetry to create the virtual environment **inside** the project directory:

    poetry config virtualenvs.in-project true

Install project and development dependencies:

    poetry install --with dev

## 3) Configure pre-commit

    poetry run pre-commit install

(Optionally run once across the repo:)

    poetry run pre-commit run --all-files

## 4) Set up environment variables

Open **.env.example** — you will find:

    DB_HOST=mariadb.iwks.fraunhofer.de
    DB_PORT=3306
    DB_USER=...
    DB_PASSWORD=...
    DB_NAME=MFA_K3I
    DB_DRIVER=mariadb+pymysql

    DB_SSL=1
    DB_SSL_VERIFY=1

Create a **.env** file at the project root (copy from `.env.example`) and fill in your credentials.
**Important:** Wrap your password with **double quotes**.

Example **.env**:

    DB_HOST=mariadb.iwks.fraunhofer.de
    DB_PORT=3306
    DB_USER=myuser
    DB_PASSWORD="VerySecret#123"
    DB_NAME=MFA_K3I
    DB_DRIVER=mariadb+pymysql

    DB_SSL=1
    DB_SSL_VERIFY=1

## 5) Test the database connection

    poetry run mfa-ingest ping-db

- If it shows **✅ DB connection OK** — alles gut.
- Otherwise, double-check the values in **.env**.

## 6) Apply database migrations

    poetry run alembic upgrade head

Verify the schema:

    poetry run mfa-ingest check-schema

- If you see **✅ Live schema looks OK (basic check)** — continue.
- Otherwise, review your schema/migration setup.

## 7) Ingest data from Excel (three stages: validate → plan → load)

Replace `"path\to\your.xlsm"` with the path to your workbook.

### a) Validate

    poetry run mfa-ingest validate "path\to\your.xlsm"

Also validate materials:

    poetry run mfa-ingest validate "path\to\your.xlsm" --check-materials

### b) Plan (preview what will be inserted)

    poetry run mfa-ingest plan "path\to\your.xlsm"

Include materials in the plan:

    poetry run mfa-ingest plan "path\to\your.xlsm" --materials

### c) Load (write to the database)

    poetry run mfa-ingest load "path\to\your.xlsm"

Useful flags:

- `--materials` — upsert the **Material** table first (insert/update).
- `--replace-process-by-name` — delete any existing process with the same name (cascade) before inserting.
- `--auto-create-materials` — create a bare material row when a component match is missing.
- `--dry-run` — execute everything but roll back at the end (no writes).
- `--database-url` — override the `.env` connection string for this run.
- `--echo-sql` — print SQL emitted by SQLAlchemy (debug).

Examples:

    poetry run mfa-ingest load "path\to\your.xlsm" --materials --dry-run
    poetry run mfa-ingest load "path\to\your.xlsm" --materials --auto-create-materials --dry-run --echo-sql
    poetry run mfa-ingest load "path\to\your.xlsm" --materials --replace-process-by-name

## 8) Process many files in a folder

Run actions across all `*.xlsm` in a directory:

    poetry run mfa-ingest walk "path\to\folder" --action validate
    poetry run mfa-ingest walk "path\to\folder" --action plan
    poetry run mfa-ingest walk "path\to\folder" --action load

Notes:
- `walk` calls the same `validate`, `plan`, and `load` logic internally.
- Flags from the single-file commands (e.g., `--check-materials`, `--materials`, `--dry-run`, `--echo-sql`) also work here.

## 9) Generate a Sankey diagram

    poetry run mfa-ingest sankey

By default the diagram HTML is saved under **outputs/sankey**.

## Component Responsibilities

- **CLI (`mfa_ingest/cli.py`)**
  Dispatches subcommands like `ping-db`, `check-schema`, `validate`, `plan`, `load`, `walk`, and `sankey`.

- **Configuration (`config/default.yaml`, `.env`)**
  Centralizes runtime settings (e.g., DB driver, SSL) and sensitive credentials (via `.env`).

- **Extraction (`mfa_ingest/extract/*`)**
  Reads and validates xlsm sheets (Process/MFA/Material) into typed, structured records.

- **Transformation (`mfa_ingest/transform/*`)**
  Harmonizes and validates records; includes material matching, process building, and cross-checks.

- **Loading (`mfa_ingest/load/loader.py`)**
  Transactional persistence into MariaDB; supports dry runs, upserts, name-based replacements.

- **ORM Models (`mfa_ingest/db_models/*`)**
  SQLAlchemy models for Process, Material, Flows, KPIs—source of truth for the schema.

- **Migrations (`alembic/*`)**
  Version and evolve the schema safely across environments.

- **Visualization (`mfa_ingest/visualize/sankey.py`)**
  Builds interactive Sankey diagrams from the live database.

# Tips & Good Practices

- **Protect Secrets**
  - Keep `.env` out of version control. Never paste credentials in issues/PRs.
  - Wrap passwords in double quotes to avoid parsing issues with special characters.

- **Use the Right Driver**
  - Default `DB_DRIVER=mariadb+mariadbconnector` works well; only switch if you know you need `pymysql`.
  - When switching drivers, re-validate connectivity (`ping-db`) and re-run `check-schema`.

- **Start with Readiness Checks**
  - Always run `ping-db` and `check-schema` after any config or migration changes.

- **Migrations Discipline**
  - Apply with `alembic upgrade head`.
  - If out-of-sync, confirm your target DB, env vars, and `alembic.ini` connection context.

- **Safe Loading**
  - Prefer `--dry-run` first to preview DB effects.
  - Use `--replace-process-by-name` for idempotent re-runs of the same process name.
  - Use `--materials` to ensure materials are inserted/updated before dependent flows.

- **Bulk Operations**
  - Use `walk` with `--action validate|plan|load` for batch folders.
  - You can pass through the same flags as single-file commands (e.g., `--dry-run`, `--materials`, `--echo-sql`).

- **Pre-commit Hooks**
  - Run `poetry run pre-commit install` once per clone.
  - Use `poetry run pre-commit run --all-files` to clean up formatting and catch issues early.

- **Logging & Debugging**
  - Tune verbosity via `config/logging.ini` or CLI flags.
  - `--echo-sql` is invaluable to inspect emitted SQL during debugging.

- **Environment Parity**
  - Use `poetry config virtualenvs.in-project true` to keep envs reproducible and local to the repo.
  - Commit `poetry.lock` for deterministic builds across machines.

- **Excel Hygiene**
  - Ensure the xlsm uses the expected sheet names/columns; validation will call these out early.
  - Use `--check-materials` to catch missing or ambiguous material mappings.

- **Outputs**
  - Sankey HTML files go to `outputs/sankey/`. You can set a custom path with `--outdir`.

- **Windows Paths**
  - Quote paths with spaces: `"C:\My Data\file.xlsm"`.
  - Prefer forward slashes or escaped backslashes in configs when possible.

- **Troubleshooting Quicklist**
  - **Connection fails** → Check `.env`, host reachability (VPN?), driver, SSL flags.
  - **Schema mismatch** → Confirm `alembic upgrade head`, correct DB target, and models in sync.
  - **Load errors** → Start with `--dry-run`, inspect logs, try `--echo-sql`, verify materials and process names.
  - **Sankey empty** → Verify data exists in the relevant tables; re-run `load` and confirm queries in `sankey.py`.
